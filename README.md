# 唯元剧创·短剧商业潜力评估系统

唯元剧创是由深圳市唯元智创科技有限公司（WEIMETA）开源的短剧、漫剧与竖屏剧剧本商业潜力评估系统。系统支持导入剧本，通过可配置的大模型生成结构化评估报告，并提供用户管理、积分管理、提示词管理、封面生成及 PDF 导出能力。

项目主要面向漫剧及短剧生产公司的 IT 团队，适合在自有环境中部署，并按团队的评估标准、模型服务和内部管理规则进行配置。

> 当前版本：v1\.0\.0

## 📖 新人使用指南

本指南面向第一次接触唯元剧创的内容人员、审片人员和项目成员，目标是用最短路径完成一次完整的「导入剧本 → AI 分析 → 查看报告 → 导出结果」。

> 开源部署环境的访问地址、账号和模型配置由部署管理员提供。普通用户默认不开放自主注册。

### 使用前检查

开始之前，请确认：

-   已获得管理员创建的登录账号；

-   管理员已配置可用的大模型服务；

-   当前账号有足够的内部使用额度；

-   已准备需要分析的剧本文档或文本内容。

### 步骤 1 ｜登录系统

打开管理员提供的系统地址，输入账号和密码进入工作台。

![guide-01-login.png](docs/images/guide-01-login.png)

如果使用首次初始化的管理员账号，请登录后立即修改默认密码。默认账号仅用于本地首次体验，不应直接用于公网部署。

### 步骤 2 ｜导入剧本

进入「导入剧本」页面后，先填写剧本名称，再上传剧本文件或直接粘贴文本。

![guide-02-upload.png](docs/images/guide-02-upload.png)

建议尽量保留剧名、人物、场景、对白、章节或集数等原始结构。结构越完整，模型越容易理解剧情关系。

确认内容无误后，点击「开始分析」。

### 步骤 3 ｜查看八节点分析进度

任务提交后，页面会显示当前节点、总体进度、已耗时和实时过程记录。

![guide-03-analysis.png](docs/images/guide-03-analysis.png)

页面按八个节点展示分析结果；实际执行顺序由所选分析模式决定：

1. 基础信息提取

2. 总体潜力评估

3. 执行摘要

4. 市场共鸣与竞争定位

5. 商业化潜力

6. 叙事与剧本基因

7. 合规性评估

8. 综合优化建议

模型、提示词、剧本长度和网络环境都会影响分析耗时与结果质量。

### 步骤 4 ｜查看结果并导出报告

分析完成后进入报告页，先查看综合评分与项目等级，再通过右侧目录逐项查看结构化分析结果。

![guide-04-report.png](docs/images/guide-04-report.png)

需要留档时，可使用页面提供的 PDF 导出功能；批量导出支持将多个 PDF 打包为 ZIP。

AI 生成的评分、结论和优化建议仅用于剧本评估、创作和项目讨论参考，不构成投资、法律、合规审查或商业收益保证。

### 管理员首次接入建议

如果你是部署管理员，建议先完成以下配置，再把账号分配给业务人员：

-   配置并测试模型 API；

-   设置内部用户和使用额度；

-   检查基础提示词模板；

-   使用示例剧本完整跑通一次八节点流程；

-   确认报告与 PDF 导出正常后，再开始正式使用。

### 常见问题

**点击开始分析后没有正常执行**：优先检查模型 API、模型名称、API Key、Redis / Worker 状态和账户额度。

**分析结果不符合团队判断标准**：先调整提示词和评分规则，再使用一批固定测试剧本进行对比验证。

**调用外部模型时数据会去哪里**：剧本文本会发送到用户自行配置的模型服务商。请在正式使用前阅读对应服务商的数据处理与隐私政策。

**可以直接把 AI 分数当成项目立项结论吗**：不建议。系统更适合作为统一初筛、内容诊断和辅助判断工具，最终项目决策仍应结合人工审核与实际业务数据。

## 🔄 核心流程

```Plain Text
导入剧本 ──► 八节点分析 ──► 结构化报告 ──► 封面与文件导出
DOCX/PDF      异步任务        在线查看        PDF（批量 ZIP）
TXT/Markdown  实时进度        历史记录        封面（需配置 OSS）

```

系统的八个分析节点包括：

1. 基础信息提取

2. 总体潜力评估

3. 执行摘要

4. 市场共鸣与竞争定位

5. 商业化潜力

6. 叙事与剧本基因

7. 合规性评估

8. 综合优化建议

分析结果由用户配置的模型和提示词生成。不同模型、提示词及输入内容可能产生不同结果。

## ✨ 功能特性

### 剧本导入与任务分析

-   支持 DOCX、PDF、TXT、Markdown 文件及文本粘贴。

-   剧本解析后关联至项目，并创建异步分析任务。

-   展示当前节点、任务进度、已耗时和过程记录。

-   支持查看历史分析任务和已生成报告。

### 结构化评估报告

-   输出总体评分、项目等级、执行摘要和市场定位。

-   分析叙事逻辑、钩子、爽点、节奏、人物、对白和悬念。

-   评估用户粘性、传播潜力、内容合规性和价值观导向。

-   给出可执行的剧本优化建议。

-   报告包含模型生成结果，仅供创作与项目判断参考。

### 三种分析模式

| 模式       | 说明                                         | 推荐场景           |
| ---------- | -------------------------------------------- | ------------------ |
| `standard` | 按完整节点执行多轮分析，质量和结构稳定性优先 | 正式评估、立项讨论 |
| `fast`     | 八节点并发执行，缩短等待时间；实际效果取决于模型及限流 | 日常初筛 |
| `ultra`    | 单次调用生成完整结果；长文本输出存在截断或结构偏差风险 | 快速预览、流程验证 |

实际速度、费用和输出质量取决于模型能力、上下文长度、提示词及网络环境。

### 模型与提示词配置

-   支持 OpenAI 兼容协议和 Anthropic 原生协议。

-   管理员可配置模型服务地址、API Key、模型名称和请求超时。

-   支持测试模型连接，并为后续任务切换运行配置。

-   支持全局报告系统提示词与封面模板配置，以及用户级覆盖；目前不支持在后台独立编辑八个节点的 Prompt。

-   提示词保存后生成历史版本，支持查看和回滚。

-   Worker 使用短时缓存，新任务会在缓存刷新后读取最新配置。

### 封面生成与文件导出

-   根据剧本标题、题材和内容摘要生成竖版海报封面。

-   封面提示词支持 `{{title}}`、`{{genre}}`、`{{excerpt}}` 和 `{{excerpt_block}}` 等占位符。

-   项目包含 MinIO 对象存储基础设施；**当前封面图片的持久化代码仍要求配置阿里云 OSS**，尚未实现无需 OSS 的本地 MinIO 封面转存。

-   报告内容以 Markdown 存储并在页面展示；目前核实的下载接口为 PDF（Puppeteer 渲染）和批量 PDF ZIP，不将 Markdown 文件下载列为已实现功能。

### 用户与积分管理

-   普通用户由管理员在后台创建和管理，系统不开放自主注册。

-   支持用户启用、停用及独立配置。

-   积分用于部署组织内部的额度分配、调用限制和消耗记录。

-   支持动作扣减、任务失败返还、积分流水和规则配置。

-   本地部署中的积分不代表向 WEIMETA 充值，具体规则以管理员配置为准。

## 🧩 开放式自定义评估 Prompt（对外参考）

开源用户可在 **管理后台 → 话术配置 → 报告系统 Prompt** 中修改评估口径，也可为不同用户配置覆盖版本。下方仅提供一份**可自行填写的系统提示词示例**，不代表 WEIMETA 的商业评估标准；示例中的维度、分数及报告模块均不是强制要求。

**使用前请注意当前实现边界：**后台可编辑 `report_system` 和 `cover_template`，支持历史版本与回滚；八个分析节点的标识及报告一级至三级章节由代码固定，`report_system` 可以调整判断口径、维度分析内容、评分原则及措辞，但**不能仅靠修改 Prompt 改变最终报告的全部章节、内置节点、评分计算器或前端展示逻辑**。要实现任意章节、无评分模式、可视化权重和多方案切换，需要二次开发并同步适配解析、报告渲染与 PDF。

以下示例适用于当前报告系统 Prompt：请将方括号中的说明替换为你自己的规则，**方括号不是运行时变量**。剧本文本由现有分析流程传入，无须在后台模板中添加 `{{script_text}}` 等未经实现的插值变量。

```text
你是本系统的剧本评估助手。请按照以下由部署者定义的标准，对实际传入的素材进行分析。

【评估目标】
[填写本次主要问题；可仅评估内容质量、商业潜力、制作可行性，也可另行定义。]

【分析范围与素材优先级】
[填写应分析的集数、篇幅、正文/大纲使用顺序；未提供的素材不能视为已经审阅。]

【评估维度】
[自行填写维度名称、子维度及各自判断依据；可自定数量，不强制采用示例维度。]

【评分口径（如需评分）】
[填写分制、等级区间、维度权重、计算方法、加减分触发条件；不设权重时不要编造加权总分。当前系统的总分提取和展示有代码约束，若需彻底取消评分或自定义自动计算，请配合修改代码。]

【分析方法】
[填写整体、逐集、逐场、角色或专项分析方式，以及优先处理的问题。]

【表达和建议】
[填写语气、分析深度、是否需要改进建议；若输出建议，应尽可能说明对应剧情位置、问题依据及修改方向。]

【通用真实性约束】
1. 区分素材事实、模型判断、风险提示和改进建议。
2. 不编造剧情、人物、平台规则、市场数据或商业收益。
3. 每项重要判断应尽量关联实际剧情证据；素材不足时明确标记。
4. 评分仅在指定口径内解释，不把模型分数作为真实市场表现预测。
5. 内容风险判断仅用于辅助筛查，不能替代正式审核。

【输出要求】
请依据上面的口径输出，并与当前系统固定的八节点及报告章节兼容。若需完全不同的章节结构、JSON 输出协议或专门的评分计算器，须先修改分析器与前端实现，不要仅依赖此系统提示词。
```

**轻量配置示例（仅供参考）：**评估前 10 集的叙事逻辑、人物动机与制作复杂度；各维度独立给出依据；需要建议时定位具体集数。不需要这些维度的用户可以全部替换。

修改后建议用一组固定、获得使用授权的测试剧本复核评分漂移、证据准确性和报告结构；保存 Prompt 不会自动证明评分可靠或商业预测有效。

## 🧠 Baseline Prompt v1\.0（八节点结构参考）

以下保留原 README 的八节点示例，供设计评估字段和二次开发时参考，**不是仓库中已部署的完整节点 Prompt**。实际 `backend/src/prompts/nodes.ts` 当前为占位模板，分析器按既定八节点执行并重建报告标题；以下 JSON 对象只是结构示例，不能直接假定替换到现有流程后就能生成 JSON 报告。示例不包含 WEIMETA 商业版本的内部评分权重、生产数据或专属规则。

以下占位符仅用于本文档示例，**并非当前系统提示词支持的全部或自动替换变量**：

-   `{{script_text}}`：完整剧本文本，必填。

-   `{{project_context}}`：题材、目标平台、目标受众等已知背景，可为空。

-   `{{previous_results}}`：前序节点结果，仅在需要承接上下文时传入。

实际系统提示词兜底文件为 `backend/refer/system_prompt.md`，节点占位模板位于 `backend/src/prompts/nodes.ts`，Ultra 另有 `backend/src/prompts/ultra.md`。下列 `00`—`08` 是文档示例编号，不是对应的九个仓库文件。当前运行流程以 Markdown 报告为主；如需真正采用示例 JSON 输出，须同步调整节点 Prompt、解析和渲染代码。

版本建议采用 `Prompt Version + Model Version + Rule Version` 三元记录。每次修改后使用固定测试剧本集回归，至少比较评分漂移、事实引用、问题诊断和建议一致性。

示例模块说明：`01` 基础信息提取、`02` 总体潜力评估、`03` 执行摘要、`04` 市场共鸣与竞争定位、`05` 商业化潜力、`06` 叙事与剧本基因、`07` 合规性评估、`08` 综合优化建议。

> 基准模板仅用于内容分析辅助。不得将模型输出视为真实市场预测、法律结论或投资回报承诺。

### 00 ｜ System Prompt

```Plain Text
你是“唯元剧创”中的剧本商业潜力分析助手，负责对短剧、漫剧与竖屏剧剧本进行结构化内容评估。

工作原则：
1. 所有事实描述必须来自输入剧本或用户明确提供的项目背景。
2. 无法确认的信息输出“未明确”或“信息不足”，禁止补写不存在的设定。
3. 明确区分：剧本事实、模型判断、风险提示与优化建议。
4. 禁止虚构播放量、收入、ROI、市场份额、平台榜单、竞品表现等外部数据。
5. 评分必须给出依据；证据不足时降低置信度。
6. 优化建议必须具体、可执行，并尽量定位到剧情、人物、节奏或结构问题。
7. 不使用“必爆”“必火”“一定盈利”等绝对化商业判断。
8. 合规节点仅做内容风险辅助识别，不替代法律意见或平台正式审核。
9. 输出使用简体中文，保持专业、简洁、结构化。
10. 如要求 JSON，仅输出合法 JSON，不附加 Markdown 代码围栏或额外解释。

统一置信度：high / medium / low。
统一证据类型：fact / model_judgment / risk / recommendation。

```

```Plain Text
输入项目背景：{{project_context}}
输入剧本：{{script_text}}

请只根据输入内容提取项目基础信息，不进行商业评分。

输出 JSON：
{
  "title": "剧名或未明确",
  "genre": ["题材标签"],
  "format": "短剧/漫剧/竖屏剧/未明确",
  "setting": "故事背景",
  "protagonists": [{"name":"人物名","identity":"身份","goal":"目标"}],
  "relationships": ["主要人物关系"],
  "core_conflict": "核心矛盾",
  "main_storyline": "主线概述",
  "target_audience_inference": ["可能受众，仅作为模型判断"],
  "evidence": [{"type":"fact","summary":"剧本依据"}],
  "missing_information": ["缺失信息"],
  "confidence": "high/medium/low"
}

不要补写剧本中不存在的人物、设定或市场信息。

```

### 02 ｜总体潜力评估

```Plain Text
从内容产品角度评估剧本当前完成度与观看驱动力。重点观察可理解性、核心冲突、人物目标、前期钩子、情绪刺激、剧情推进、差异化和持续观看动力。

```

### 03 ｜执行摘要

```Plain Text
项目背景：{{project_context}}
前序分析：{{previous_results}}
剧本：{{script_text}}

生成一份适合内容负责人快速阅读的执行摘要。摘要必须回答：这是一个什么故事、最大的内容卖点是什么、最值得关注的问题是什么、当前最应该优先解决什么。

输出 JSON：
{
  "story_in_one_sentence": "一句话故事",
  "core_hook": "核心内容卖点",
  "audience_value": "用户为什么可能继续看",
  "top_strengths": ["最多3项"],
```

## 🚀 快速开始

### 环境要求

-   Docker

-   Node\.js 20 或更高版本

-   pnpm

### 一键启动

首次运行前，请确认 Docker Engine 已启动；在 `frontend/.env.local` 中配置 `VITE_API_BASE_URL=/api`，使前端登录等请求正确转发。首次安装如遇镜像拉取失败、端口占用或浏览器依赖安装失败，应先排查具体日志，不能仅凭启动脚本的就绪提示判断所有服务正常。

```Bash
./dev.sh --init

```

该命令用于安装依赖、启动 PostgreSQL、Redis 和 MinIO、执行数据库迁移，并初始化管理员账号。

日常启动：

```Bash
./dev.sh

```

启动完成后访问：

```Plain Text
http://localhost:3000

```

管理员账号默认使用 `admin`，首次密码由 `./dev.sh --init` 随机生成，并由 seed 脚本输出到当前终端。请在首次登录后立即修改密码并将其保存到密码管理器；不要把密码写入 README、Issue 或提交记录。

### 手动启动

```Bash
pnpm install
cp backend/.env.example backend/.env
# 编辑 backend/.env：至少设置 SEED_ADMIN_PASSWORD 及服务凭据、连接信息
# 创建/编辑 frontend/.env.local，填写 VITE_API_BASE_URL=/api

docker compose --env-file backend/.env -f backend/docker-compose.yml up -d

pnpm --filter backend db:migrate
pnpm --filter backend db:seed
pnpm --filter backend db:seed:prompts

pnpm --filter backend dev
pnpm --filter backend worker
pnpm --filter frontend dev

```

服务默认地址：

| 服务     | 地址                    |
| -------- | ----------------------- |
| 前端     | `http://localhost:3000` |
| 后端 API | `http://localhost:5174` |

完整配置项见 backend/\.env\.example。常用变量如下：

| 变量           | 说明                           |

当前仓库未包含 `SECURITY.md`，请先参照文末联系方式私下报告安全问题；生产环境还应限制数据库、Redis 和对象存储的网络访问，并将备份、日志和上传文件排除在 Git 之外。

## 🔧 Prompt 与运行配置

本 README 提供开放式系统 Prompt 范例及八节点**结构参考**；仓库实际节点 Prompt 仍为占位模板。当前运行时接入位置如下：

| 文件                             | 用途                       |
| -------------------------------- | -------------------------- |
| `backend/refer/system_prompt.md` | 报告分析系统提示词兜底文件 |
| `backend/src/prompts/ultra.md`   | Ultra 模式用户提示词       |
| `backend/src/prompts/nodes.ts`   | 八节点分析提示词模板       |

后台修改 Prompt 后由版本管理机制保存，Worker 新任务在缓存刷新后使用最新配置。仅在**需要初始化数据库中的默认 Prompt** 时使用以下命令；它不是每次编辑后的必执行步骤：

```Bash
pnpm --filter backend db:seed:prompts

```

正式业务环境建议同时记录 `Prompt Version + Model Version + Rule Version`，并用固定测试剧本集进行回归。
